Omni SOC
Problema Arquitectura Escenarios Tecnologías Planificación Equipo

Una pyme simulada, vigilada como lo haría un equipo de seguridad.

Omni SOC es una red virtualizada con servidores, clientes y cortafuegos, sobre la que funciona un pequeño Centro de Operaciones de Seguridad: centraliza logs, detecta ataques, avisa y documenta la respuesta. Todo se despliega como código.

Ver el repositorio Ver el tablero de tareas

El problema

Muchas pymes no tienen personal ni presupuesto para un departamento de ciberseguridad. Cuando sufren un incidente, lo descubren tarde o no lo descubren nunca.

Nadie monitoriza el tráfico y los intentos de intrusión pasan desapercibidos. Omni SOC aborda esa falta de visibilidad y de capacidad de respuesta en infraestructuras pequeñas, con herramientas libres y un despliegue reproducible.

  • Pymes sin SOC propio, como modelo realista de cómo ganar visibilidad.
  • Administradores y técnicos de red, que son quienes operan la monitorización y la respuesta.
  • Estudiantes y técnicos en formación, como laboratorio para aprender a montar y operar un SOC básico.

Arquitectura

Un cortafuegos pfSense separa la red en VLANs por función. Cada equipo lleva un agente de Wazuh que envía sus registros al servidor del SOC, y Suricata analiza el tráfico entre segmentos. El atacante vive en un segmento de laboratorio aparte.

Escenarios de prueba

Cada ataque del red team tiene una detección esperada del blue team. El objetivo es detectar el 100 % de los escenarios definidos y que la alerta llegue al panel en menos de un minuto.

EscenarioAtaqueDetección esperada
Fuerza brutaCU2 Hydra contra un servicio expuesto, por ejemplo ssh. Wazuh registra los intentos fallidos y genera una alerta en el panel.
Escaneo de redCU3 Escaneo de puertos con nmap contra la red simulada. Suricata reconoce el patrón y el SIEM muestra una alerta de reconocimiento.
Malware de pruebaCU4 Descarga o ejecución del fichero EICAR en un cliente. El agente de Wazuh detecta la firma e identifica el equipo afectado.
RespuestaCU5 Cualquiera de los anteriores. El analista sigue el procedimiento: aislar el equipo, revisar logs, contener y documentar causa y acción.

Tecnologías

Herramientas libres y ampliamente usadas en entornos reales, elegidas para que el laboratorio se parezca lo máximo posible a un SOC de verdad.

Red y servicios

  • pfSense cortafuegos y VLANs
  • Windows Server Active Directory
  • Linux servidores
  • Kea DHCP
  • Apache web

Seguridad

  • Wazuh SIEM y panel
  • Suricata IDS de red
  • Kali Linux ataques controlados
  • Nmap · Hydra · EICAR

Automatización

  • VirtualBox virtualización
  • Vagrant máquinas como código
  • Ansible configuración
  • Bash scripts

Formatos y trabajo

  • YAML playbooks
  • Ruby Vagrantfile
  • XML reglas de Wazuh
  • Git y GitHub versiones y kanban

Estructura del repositorio

La infraestructura entera vive en el repositorio. Clonarlo y lanzar el despliegue debe levantar el mismo entorno en cualquier equipo que cumpla los requisitos de virtualización, sin configurar nada a mano.

Las instrucciones de despliegue se añadirán al README cuando estén cerradas.

Omni-SOC/
├── infra/          máquinas y red como código
├── monitorizacion/ Wazuh y Suricata
├── blue-team/      reglas y respuesta
├── red-team/       ataques controlados
├── scripts/        utilidades
└── docs/           documentación
